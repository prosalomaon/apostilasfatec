Teoria & Conceito: Aula 13 — Encapsulamento: Modificadores e Getters/Setters

O encapsulamento é um dos pilares fundamentais da Programação Orientada a Objetos (OO). Ele consiste em "esconder" os detalhes internos de como uma classe funciona, expondo apenas o que é necessário para quem a utiliza. A ideia central é separar o comportamento interno da interface (métodos públicos) que a classe disponibiliza para seus clientes.

1. O que é Encapsular?

Encapsular é proteger os dados de uma classe para que eles não fiquem em um estado inconsistente. Imagine um objeto Conta: se o atributo saldo for público, qualquer um pode alterá-lo para um valor negativo ou inválido sem passar por nenhuma conferência. Ao encapsular, forçamos que qualquer interação com o dado passe por um método que pode conter regras de negócio e validações.

  • Analogia do Mundo Real: Quando você dirige um carro, interage com os pedais e o volante (interface). Você não precisa entender como a explosão do combustível move os pistões (implementação interna). Se o fabricante trocar o motor, você não precisa "reaprender" a dirigir, pois a interface continua a mesma.

2. Modificadores de Acesso: private e public

Os modificadores de acesso (ou de visibilidade) determinam quem pode ver e usar os membros de uma classe.

  • private (Privado): É o nível mais restritivo. Membros (atributos ou métodos) marcados como private só podem ser acessados e manipulados por métodos dentro da própria classe. É a prática recomendada para quase todos os atributos de uma classe.
  • public (Público): Permite que qualquer outra classe no projeto acesse o membro. Geralmente, os métodos que representam os "serviços" que a classe presta são públicos.

Exemplo de erro por falta de acesso:

public class Conta {
    private double saldo; // Atributo protegido
}

public class Principal {
    public static void main(String[] args) {
        Conta c = new Conta();
        c.saldo = 1000; // ERRO DE COMPILAÇÃO: 'saldo' tem acesso privado [19, 20]
    }
}

3. Métodos Getters e Setters

Como os atributos são privados, precisamos de uma maneira controlada de lê-los e modificá-los. Para isso, utilizamos a convenção de métodos Get (pegar) e Set (configurar).

  • Getters (Acessores): Métodos que retornam o valor de um atributo. Geralmente não recebem parâmetros e possuem um tipo de retorno condizente com o atributo.
  • Setters (Modificadores): Métodos que permitem alterar o valor de um atributo. Eles recebem um parâmetro e geralmente possuem o tipo de retorno void.

Exemplo Prático com Validação:

public class Aluno {
    private String nome;
    private double media;

    // Getter para o nome
    public String getNome() {
        return nome; [26, 27]
    }

    // Setter para o nome
    public void setName(String nome) {
        this.nome = nome; [27, 28] // 'this' diferencia o atributo do parâmetro
    }

    // Setter para a média com VALIDAÇÃO de integridade [10, 29]
    public void setMedia(double media) {
        if (media >= 0.0 && media <= 10.0) {
            this.media = media;
        } else {
            System.out.println("Média inválida!");
        }
    }
}

4. Vantagens da Engenharia de Software

O uso de variáveis de instância private e métodos de acesso public traz benefícios cruciais:

  • Ocultamento de Informações: O cliente da classe sabe o que o método faz, mas não como ele faz. Isso permite que você mude a implementação interna sem quebrar o código de quem usa a sua classe.
  • Controle de Integridade: Você pode impedir que um saldo fique negativo ou que um CPF inválido seja cadastrado.
  • Flexibilidade: Se no futuro você decidir que o saldo deve sempre ser exibido somado ao limite, basta alterar o método getSaldo(). Todas as partes do sistema que chamam esse método serão atualizadas automaticamente.
  • Baixo Acoplamento: As classes tornam-se mais independentes, facilitando a manutenção e a expansão do software.

Exemplos de Código

Exemplo 1: O Cenário de Erro (Sem Encapsulamento)

Objetivo: Mostrar o perigo de deixar os atributos públicos (public). Qualquer parte do sistema pode inserir dados inválidos e quebrar as regras de negócio.

// CLASSE MAL PROJETADA (Sem proteção)
class ContaBancaria {
    public String titular;
    public double saldo; // Perigo: qualquer um altera diretamente
}

// PROGRAMA PRINCIPAL
public class TesteSemEncapsulamento {
    public static void main(String[] args) {
        ContaBancaria conta = new ContaBancaria();
        conta.titular = "Alex";
        
        // O desastre acontece aqui:
        conta.saldo = -5000.0; // Saldo negativo direto sem validação!
        
        System.out.println(conta.titular + " tem saldo de: R$ " + conta.saldo);
    }
}

Exemplo 2: Encapsulamento Básico (Modificadores + Get/Set)

Objetivo: Aplicar a regra de ouro do encapsulamento: atributos sempre privados (private), leitura e escrita controladas por métodos públicos (public).

class Aluno {
    // 1. Atributos privados (Escondidos do mundo exterior)
    private String nome;
    private double nota;

    // 2. Construtor
    public Aluno(String nome, double nota) {
        this.nome = nome;
        setNota(nota); // Usa o setter para garantir a regra desde o início
    }

    // 3. Método Getter (Leitura)
    public String getNome() { return this.nome; }
    public double getNota() { return this.nota; }

    // 4. Método Setter (Escrita com Controle de Integridade)
    public void setNota(double novaNota) {
        if (novaNota >= 0 && novaNota <= 10) {
            this.nota = novaNota;
        } else {
            System.out.println("Erro: Nota inválida! Mantendo o valor anterior.");
        }
    }
}

Exemplo 3: Intermediário (Atributo de "Apenas Leitura")

Objetivo: Explicar que nem todo atributo precisa de um Setter. Se o dado não deve mudar após ser criado (ex: CPF, ID, Data de Nascimento), criamos apenas o Getter.

class Funcionario {
    private final String cpf; // 'final' reforça a imutabilidade
    private double salario;

    public Funcionario(String cpf, double salarioInicial) {
        this.cpf = cpf;
        this.salario = salarioInicial;
    }

    // Apenas Getter para o CPF. Ninguém pode alterar o CPF de um funcionário cadastrado!
    public String getCpf() { return this.cpf; }

    public double getSalario() { return this.salario; }
    
    // O salário não muda diretamente, muda através de uma regra de negócio (Aumento)
    public void aumentarSalario(double porcentagem) {
        if (porcentagem > 0) {
            this.salario += this.salario * (porcentagem / 100);
        }
    }
}

Exemplo 4: Avançado (Encapsulamento com Swing e Boas Práticas)

Objetivo: Juntar os conceitos de encapsulamento com a interface gráfica, demonstrando como o encapsulamento protege o estado de um objeto em uma aplicação real acionada por eventos.

import javax.swing.*;
import java.awt.FlowLayout;

// CLASSE DE NEGÓCIO ENCAPSULADA
class Termometro {
    private double temperaturaCelsius;

    public double getCelsius() { return temperaturaCelsius; }

    // Controle de integridade severo (Zero Absoluto da física)
    public boolean setCelsius(double temp) {
        if (temp >= -273.15) {
            this.temperaturaCelsius = temp;
            return true; // Sucesso
        }
        return false; // Falha na validação
    }

    // Getter calculado (Não existe o atributo fahrenheit na memória, ele é gerado na hora)
    public double getFahrenheit() {
        return (temperaturaCelsius * 9 / 5) + 32;
    }
}

// INTERFACE SWING
public class TelaTermometro extends JFrame {
    private Termometro termometro = new Termometro();

    public TelaTermometro() {
        super("Controle de Temperatura");
        setLayout(new FlowLayout());

        JTextField txtInput = new JTextField(10);
        JButton btnAtualizar = new JButton("Definir Temp (°C)");

        btnAtualizar.addActionListener(e -> {
            try {
                double tempDigitada = Double.parseDouble(txtInput.getText());
                
                // O Swing tenta atualizar o objeto encapsulado
                if (termometro.setCelsius(tempDigitada)) {
                    JOptionPane.showMessageDialog(this, 
                        "Sucesso!\nFahrenheit: " + termometro.getFahrenheit() + " °F");
                } else {
                    JOptionPane.showMessageDialog(this, "Erro: Abaixo do zero absoluto!");
                }
            } catch (NumberFormatException ex) {
                JOptionPane.showMessageDialog(this, "Digite um número válido!");
            }
        });

        add(new JLabel("Graus Celsius:"));
        add(txtInput);
        add(btnAtualizar);

        setSize(300, 150);
        setDefaultCloseOperation(JFrame.EXIT_ON_CLOSE);
        setLocationRelativeTo(null);
    }

    public static void main(String[] args) {
        new TelaTermometro().setVisible(true);
    }
}

Dicas & Lembretes

  • Não crie Getters/Setters indiscriminadamente: Só forneça esses métodos se houver uma real necessidade de leitura ou escrita. Se um atributo for usado apenas internamente, ele não precisa de get/set.
  • Encapsulamento de Comportamento: Encapsular não é apenas proteger atributos; é também esconder a lógica de métodos complexos, deixando-os privados caso sejam apenas auxiliares para a própria classe.
  • Convenção JavaBeans: Siga o padrão getAtributo() e setAtributo(). Muitas bibliotecas e frameworks Java (como Hibernate e Spring) dependem dessa nomenclatura para funcionar corretamente.
  • Atalhos da IDE: No Eclipse, você pode gerar todos os getters e setters rapidamente usando o atalho Alt + Shift + S ou Ctrl + 3 e digitando "ggas" (Generate Getters and Setters).
