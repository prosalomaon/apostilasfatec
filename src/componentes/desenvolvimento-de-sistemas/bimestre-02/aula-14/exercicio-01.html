Enunciado

Quando criamos um objeto no mundo real, muitas vezes ele não pode existir sem certas informações fundamentais. Por exemplo, não faz sentido emitir uma passagem aérea sem o nome do passageiro e o número do voo. Se permitirmos que o objeto seja criado "vazio" para ser preenchido depois, corremos o risco de gerar dados inconsistentes no sistema.

Os Construtores servem justamente para garantir que um objeto nasça com os dados obrigatórios já validados. Além disso, quando os parâmetros do construtor têm o mesmo nome dos atributos da classe, utilizamos a palavra-chave this para guiar o Java sobre quem é a variável local (parâmetro) e quem é o atributo da instância.

Nesta atividade, você vai corrigir um sistema de terminal que está permitindo a criação de passagens fantasmas (sem dados) e aplicar o encadeamento de construtores para facilitar a emissão de passagens promocionais fixas.

Preparação

  1. Abra a sua IDE ou editor de código (Eclipse, IntelliJ ou VS Code).
  2. Crie um novo projeto ou arquivo Java.
  3. Crie um arquivo chamado EmissorPassagemConsole.java.
  4. Cole o Código Base fornecido abaixo dentro do arquivo.

Código Base

import java.util.Scanner;

// ==========================================
// CLASSE BILHETE (ALUNO DEVERÁ MODIFICAR)
// ==========================================
class Bilhete {
    public String nomePassageiro;
    public String numeroVoo;
    public double precoAssento;

    // Atualmente não há construtores definidos. 
    // O Java usa o construtor padrão vazio automático: Bilhete()
}

// ==========================================
// SISTEMA PRINCIPAL EM CONSOLE (PRONTO)
// ==========================================
public class EmissorPassagemConsole {
    public static void main(String[] args) {
        Scanner leitor = new Scanner(System.in);
        
        System.out.println("=== SISTEMA DE EMISSÃO DE PASSAGENS ===");
        System.out.println("1 - Emitir Bilhete Completo");
        System.out.println("2 - Emitir Bilhete Promocional Padrão");
        System.out.print("Escolha uma opção: ");
        int opcao = leitor.nextInt();
        leitor.nextLine(); // Limpa o buffer do teclado

        if (opcao == 1) {
            System.out.print("Digite o nome do passageiro: ");
            String nome = leitor.nextLine();
            System.out.print("Digite o número do voo: ");
            String voo = leitor.nextLine();
            System.out.print("Digite o preço da passagem: R$ ");
            double preco = leitor.nextDouble();

            // MODO VULNERÁVEL ATUAL: Criando objeto vazio e preenchendo depois
            Bilhete b1 = new Bilhete();
            b1.nomePassageiro = nome;
            b1.numeroVoo = voo;
            b1.precoAssento = preco;

            System.out.println("\n[SUCESSO] Bilhete Customizado Emitido!");
            System.out.println("Passageiro: " + b1.nomePassageiro + " | Voo: " + b1.numeroVoo + " | Preço: R$ " + b1.precoAssento);

        } else if (opcao == 2) {
            System.out.print("Digite o nome do passageiro para o voo PROMO: ");
            String nomePromo = leitor.nextLine();

            // MODO ATUAL: Exige preenchimento manual e repetitivo de dados fixos
            Bilhete bPromo = new Bilhete();
            bPromo.nomePassageiro = nomePromo;
            bPromo.numeroVoo = "PROMO99";
            bPromo.precoAssento = 99.90;

            System.out.println("\n[SUCESSO] Bilhete Promocional Emitido!");
            System.out.println("Passageiro: " + bPromo.nomePassageiro + " | Voo: " + bPromo.numeroVoo + " | Preço: R$ " + bPromo.precoAssento);
        } else {
            System.out.println("Opção inválida!");
        }

        leitor.close();
    }
}

O Desafio

Sua missão é blindar a classe Bilhete usando construtores e a referência this para impedir a existência de objetos sem dados no terminal. Siga os passos:

  • Modificadores de Acesso e Getters: Altere a visibilidade dos três atributos da classe Bilhete (nomePassageiro, numeroVoo e precoAssento) de public para private. Crie apenas os métodos Getters públicos para permitir a leitura controlada desses dados. Não crie métodos Setters.
  • Construtor Principal (Tratando Ambiguidade com this):
    • Crie um construtor que obrigue o recebimento de todos os três parâmetros: public Bilhete(String nomePassageiro, String numeroVoo, double precoAssento).
    • Como os parâmetros locais têm exatamente o mesmo nome dos atributos da classe, utilize a palavra-chave this obrigatoriamente para assinalar e atualizar os atributos da instância (ex: this.nomePassageiro = nomePassageiro;).
  • Construtor em Cadeia (this()):
    • Crie um segundo construtor que receba apenas o nome do passageiro: public Bilhete(String nomePassageiro).
    • Dentro do corpo deste construtor, use a palavra-chave this(...) obrigatoriamente na primeira linha para chamar o seu construtor principal. Repasse o nome recebido e configure os dados padrões fixos da promoção: Voo "PROMO99" e preço 99.90.
  • Refatoração da Classe Principal:
    • No bloco da opcao == 1, altere o código para instanciar o objeto passando as três variáveis coletadas diretamente dentro dos parênteses do new Bilhete(nome, voo, preco).
    • No bloco da opcao == 2, altere o código para usar o seu segundo construtor, passando apenas a variável nomePromo dentro do new Bilhete(nomePromo).
    • Ajuste as linhas de exibição final de dados (System.out.println) para acessarem os novos métodos Getters públicos que você criou, já que o acesso direto às variáveis agora está bloqueado.

Orientações Finais

  • O que será avaliado:
    • Uso correto de this.atributo = parametro para resolver o conflito de escopo (Shadowing).
    • Implementação do construtor em cadeia utilizando this(...) corretamente como a primeira instrução do bloco secundário.
    • Eliminação completa de atribuições diretas de variáveis (ex: b.nomePassageiro = ...) e substituição pelo uso dos Getters.
  • Dica Importante: Assim que você criar o primeiro construtor na classe Bilhete, o Java desativará automaticamente o construtor padrão invisível vazio. Isso fará com que as linhas antigas new Bilhete() fiquem vermelhas acusando erro de compilação. Esse é o comportamento esperado para provar que seu objeto foi blindado com sucesso!
