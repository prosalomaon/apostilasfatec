Teoria & Conceitos

A herança é um dos pilares fundamentais da programação orientada a objetos (POO), permitindo que uma nova classe seja criada adquirindo os membros de uma classe já existente, possivelmente aprimorando-os ou modificando-os. O objetivo central é promover a reutilização de software, economizando tempo no desenvolvimento e aumentando a confiabilidade do sistema, já que novas classes podem ser baseadas em códigos já testados e depurados.

1. O Relacionamento "É UM" (Is-a)

Diferente da composição, que representa o relacionamento "tem um", a herança define um relacionamento do tipo "é um". Em uma hierarquia de herança, um objeto de uma subclasse pode ser tratado como um objeto de sua superclasse. Por exemplo, um Ebook é um Livro, e um Gerente é um Funcionario.

  • Superclasse (Classe Mãe): A classe mais geral de onde os membros são herdados.
  • Subclasse (Classe Filha): A classe mais específica que herda as características da superclasse e pode adicionar novos comportamentos ou atributos.

2. A Palavra-Chave extends

No Java, utilizamos a palavra-chave extends na declaração da classe para indicar de qual classe ela está herdando. É importante notar que o Java suporta apenas a herança única, o que significa que uma classe pode ter apenas uma superclasse direta.

Exemplo Prático: Hierarquia de Funcionários

// Superclasse geral
public class Funcionario {
    protected String nome;
    protected double salario;

    public double getBonificacao() {
        return this.salario * 0.10; // 10% de bônus padrão [16]
    }
}

// Subclasse especializada
public class Gerente extends Funcionario {
    private int senha;

    // O Gerente herda nome, salario e getBonificacao automaticamente [8]
    public boolean autentica(int senha) {
        return this.senha == senha;
    }
}

3. A Hierarquia Universal: Classe Object

Se uma classe não especifica explicitamente de quem ela herda, o Java automaticamente define que ela extends Object. Por isso, a classe Object é considerada a superclasse direta ou indireta de todas as classes no ecossistema Java, fornecendo métodos universais como toString() e equals().

4. Controle de Acesso e o Modificador protected

Ao trabalhar com herança, o encapsulamento ganha uma nova camada de visibilidade. Enquanto membros private não são acessíveis nem mesmo para subclasses, o modificador protected oferece um meio-termo: ele torna o membro visível para a própria classe, para suas subclasses e para outras classes dentro do mesmo pacote.

Ponto de atenção: Embora facilite o acesso direto, o uso excessivo de protected pode criar classes "frágeis", onde uma mudança na superclasse pode quebrar acidentalmente as subclasses. A boa prática recomenda, sempre que possível, manter atributos private e acessá-los via métodos public ou protected herdados.

5. Construtores em Hierarquias de Herança

Os construtores não são herdados. Quando um objeto de uma subclasse é instanciado, ocorre uma cadeia de chamadas de construtores: a subclasse deve, obrigatoriamente, chamar o construtor de sua superclasse direta como primeira tarefa.

  • A referência super(): Se não for especificado, o compilador insere uma chamada implícita para o construtor padrão (sem argumentos) da superclasse. Caso a superclasse exija parâmetros, deve-se usar super(argumentos) explicitamente.

Exemplo Prático: Cadeia de Construtores

public class Ebook extends Livro {
    public Ebook(Autor autor) {
        // Delega a inicialização para o construtor de Livro [13]
        super(autor); 
    }
}

6. Reescrevendo Métodos: O Polimorfismo Inicial

Uma subclasse pode reescrever (sobrescrever) métodos herdados para fornecer uma implementação mais adequada ao seu tipo específico.

  • Anotação @Override: Utilizada para notificar o compilador de que o método pretende sobrescrever um método da classe mãe, ajudando a capturar erros de assinatura em tempo de compilação.
  • Chamando a Versão Original: Se a subclasse precisar realizar a lógica da mãe e adicionar algo mais, ela pode invocar a versão original usando super.metodo().

Exemplo Prático: Sobrescrita de Método

public class Gerente extends Funcionario {
    @Override
    public double getBonificacao() {
        // Usa o cálculo da mãe e soma um bônus adicional de R$ 1000 [37, 38]
        return super.getBonificacao() + 1000;
    }
}

7. Especialização vs. Generalização

A modelagem orientada a objetos utiliza a herança para organizar o código em diferentes níveis de abstração.

  • Generalização: Agrupar características comuns de classes distintas em uma superclasse mais genérica (ex: Animal).
  • Especialização: Criar subclasses que adicionam comportamentos específicos a um conceito geral (ex: Cachorro estendendo Animal).

Consideração de Design: Herança ou Composição?

Embora poderosa, a herança deve ser usada com cautela, pois cria um alto acoplamento entre as classes. Muitos especialistas e autores renomados sugerem "favorecer a composição em relação à herança" sempre que possível, utilizando a herança estritamente para relacionamentos onde a semântica "é um" é indiscutível e estável.

Tabela Comparativa para Fixação

Termo O que faz? Analogia
extends Cria o vínculo de herança. "Herdei os olhos azuis do meu pai."
super Acessa métodos ou construtores do pai. "Pai, me empresta aquela sua ferramenta?"
@Override Reescreve um método herdado. "Meu pai cozinha feijão, mas eu faço o meu com bacon."
protected Modificador de acesso para herança. "Apenas quem é da família pode mexer nisso."

Exemplos de Código

1. Nível Básico: O Conceito "É UM"

Neste nível, mostramos que a subclasse é uma versão da superclasse. O foco aqui é a palavra-chave extends.

// Superclasse (Pai)
class Animal {
    String nome;

    void comer() {
        System.out.println(nome + " está comendo...");
    }
}

// Subclasse (Filho)
class Cachorro extends Animal {
    void latir() {
        System.out.println("Au Au!");
    }
}

public class ExemploBasico {
    public static void main(String[] args) {
        Cachorro meuPet = new Cachorro();
        meuPet.nome = "Rex"; // Herdado de Animal
        meuPet.comer();      // Herdado de Animal
        meuPet.latir();      // Próprio de Cachorro
    }
}

2. Nível Intermediário: Sobrescrita e a palavra super

Aqui as coisas ficam interessantes. A filha pode herdar o comportamento, mas pode querer fazê-lo de um jeito diferente (Sobrescrita). Também aprendemos a chamar o construtor do pai com o super.

class Funcionario {
    String nome;
    double salario;

    Funcionario(String nome, double salario) {
        this.nome = nome;
        this.salario = salario;
    }

    double calcularBonus() {
        return this.salario * 0.10; // Bônus padrão de 10%
    }
}

class Gerente extends Funcionario {
    Gerente(String nome, double salario) {
        super(nome, salario); // Chama o construtor da Superclasse
    }

    @Override // Avisa ao compilador que estamos mudando o comportamento do pai
    double calcularBonus() {
        // Usa o bônus do pai + um bônus extra fixo de 500
        return super.calcularBonus() + 500; 
    }
}

Dica: O @Override não é obrigatório, mas é uma rede de segurança. Se você digitar o nome do método errado, o Java te avisa na hora.

3. Nível Avançado: Classes Abstratas e Polimorfismo

No nível avançado, usamos abstract para garantir que ninguém instancie a classe "mãe" (que é genérica demais) e mostramos o poder do polimorfismo.

// Classe abstrata: Não pode ser instanciada (new Forma() daria erro)
abstract class Forma {
    abstract double calcularArea(); // Obriga as filhas a implementarem
}

class Quadrado extends Forma {
    double lado;
    Quadrado(double lado) { this.lado = lado; }
    
    @Override
    double calcularArea() { return lado * lado; }
}

class Circulo extends Forma {
    double raio;
    Circulo(double raio) { this.raio = raio; }
    
    @Override
    double calcularArea() { return Math.PI * Math.pow(raio, 2); }
}

public class SistemaGeométrico {
    public static void main(String[] args) {
        // POLIMORFISMO: Uma lista de "Formas" que contém objetos diferentes
        Forma[] formas = { new Quadrado(5), new Circulo(3) };

        for (Forma f : formas) {
            // O Java sabe exatamente qual calcularArea() chamar em tempo de execução
            System.out.println("Área: " + f.calcularArea());
        }
    }
}

Dicas & Lembretes

  • A Regra do "É UM": Só use herança se a classe filha passar no teste lógico "É UM".
    • Exemplo correto: Um Carro é um Veículo. Um Cachorro é um Animal.
    • Exemplo errado: Uma Janela é um Botão? Não, a janela tem um botão. Se o relacionamento for "tem um", usamos composição (criar o objeto dentro da classe), e não herança.
  • Herança Única (Regra de Ouro do Java): O Java não permite herança múltipla de classes. Uma classe filha só pode ter uma única classe mãe direta. Códigos como class Carro extends Veiculo, Motor geram erro de compilação automático!
  • O "Pedágio" do Construtor (super): Quando você instancia um filho, o Java obrigatoriamente constrói o pai primeiro. Se a classe pai tiver um construtor customizado (com parâmetros), você é obrigado a chamá-lo usando super(parametros) logo na primeira linha do construtor da classe filha.
  • A Proteção do protected:
    • Se um atributo for private na classe pai, o filho não consegue mexer nele diretamente.
    • Se for public, qualquer um mexe.
    • O meio-termo ideal para herança é o protected: o atributo fica visível para as classes filhas (e classes do mesmo pacote), mas protegido do resto do sistema.
  • A Rede de Segurança do @Override: Sempre que for reescrever um método herdado do pai, use a anotação @Override. Ela não altera o funcionamento, mas avisa ao compilador o que você está fazendo. Se você errar uma única letra no nome do método (ex: escrever comer() no pai e commer() no filho), o Java acusa o erro na hora e te salva de um bug silencioso.
  • O Ponto Final (final):
    • Uma classe marcada como final (como a classe String do próprio Java) barra a herança. Ninguém pode dar extends nela.
    • Um método marcado como final pode ser herdado e usado pelos filhos, mas nunca poderá ser sobrescrito (@Override).

Como é aplicado em projetos reais

1. Gateways de Pagamento (E-commerce)

Em qualquer grande site de vendas (como Amazon ou Mercado Livre), o sistema precisa processar pagamentos de formas diferentes, mas todos os pagamentos seguem um fluxo básico: validar dados, cobrar e gerar um recibo.

  • Superclasse (Payment): Guarda o ID da transação, o valor e o método comum processar().
  • Subclasses (PixPayment, CreditCardPayment, BoletoPayment): Herdam a estrutura, mas cada uma reescreve (@Override) o método processar() para falar com bancos diferentes.
// Código simplificado do mundo real
public abstract class ProcessadorPagamento {
    protected double valor;

    public void registrarLog() {
        System.out.println("Iniciando transação de R$" + valor);
    }
    public abstract void autorizar(); // Cada filho resolve o seu
}

public class ProcessadorPix extends ProcessadorPagamento {
    @Override
    public void autorizar() {
        super.registrarLog(); // Reutiliza a base do pai
        // Lógica específica para gerar o QR Code do Pix
    }
}

2. Desenvolvimento de Games (Engine de Jogos)

Seja em jogos independentes ou em grandes produções (como Minecraft ou RPGs), tudo o que se move na tela compartilha propriedades físicas básicos: posição X e Y, velocidade e peso.

  • Superclasse (Entity ou GameObject): Define a posição no mapa e o método atualizarPosicao().
  • Subclasses (Player, Monster, NPC): Herdam o movimento básico. O Monster adiciona inteligência para perseguir o jogador, enquanto o Player adiciona leituras dos comandos do teclado.

Por que usam aqui? Se a física do jogo mudar (por exemplo, a gravidade diminuir), o programador altera apenas a classe mãe Entity, e automaticamente todos os monstros, itens e jogadores do jogo inteiro passam a flutuar!

3. Controle de Acesso e Usuários (SaaS / Netflix)

Em plataformas de streaming ou sistemas empresariais, existem diferentes níveis de usuários, mas todos eles precisam de e-mail e senha para fazer login.

  • Superclasse (Usuario): Possui email, senha e o método fazerLogin().
  • Subclasses (Cliente, Administrador, Suporte): O administrador herda o login do cliente, mas ganha métodos como deletarConta() ou alterarPreco().

O uso do protected na prática: O atributo senha na classe mãe é marcado como protected. Isso permite que a classe Administrador possa resetar a senha de um usuário diretamente caso ele peça suporte, mas impede que invasores externos acesssem a senha de fora do sistema.

4. Frameworks Web e Aplicativos (Android / Spring)

No Android, para criar uma tela, você não cria o comportamento do zero. Você herda de uma classe do Google chamada Activity.

// No mundo real do desenvolvimento Android:
public class MinhaTelaLogin extends AppCompatActivity {
    @Override
    protected void onCreate(Bundle savedInstanceState) {
        super.onCreate(savedInstanceState); // Diz ao Android: "Monte a tela padrão"
        setContentView(R.layout.activity_login); // Adiciona o meu design
    }
}

Por que usam aqui? O Google gastou anos programando como uma tela gerencia bateria, rotação e toque. Ao dar extends AppCompatActivity, seu aplicativo ganha tudo isso de graça em apenas uma linha.
