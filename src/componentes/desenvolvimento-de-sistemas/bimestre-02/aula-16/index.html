Teoria & Conceitos

O polimorfismo é um dos conceitos mais poderosos da programação orientada a objetos, sendo uma consequência direta do uso da herança e de interfaces. Ele permite que um sistema seja desenhado para ser facilmente extensível, possibilitando que novas classes sejam adicionadas com mínima modificação nas partes gerais do programa.

1. O que é Polimorfismo?

A palavra polimorfismo significa "múltiplas formas". No contexto do Java, refere-se à capacidade de um objeto ser referenciado de várias maneiras.

É fundamental entender que um objeto não se transforma: ele nasce de um tipo específico e morre como esse tipo na memória. O que muda é a referência (a variável) que utilizamos para alcançá-lo. Por exemplo, se a classe Gerente estende Funcionario, um objeto do tipo Gerente é um Funcionario e, portanto, pode ser guardado em uma variável do tipo Funcionario.

Exemplo Prático de Referência:

// Um Gerente é instanciado, mas referenciado como um Funcionario (Tipo Geral)
Funcionario f = new Gerente();

Neste caso, a variável f guarda uma referência para um Funcionario, mas o objeto real na memória é um Gerente.

2. Programando voltado ao "Tipo Geral"

O polimorfismo permite ao desenvolvedor "programar no geral" em vez de "no específico". Ao utilizar referências de superclasses ou interfaces, podemos criar métodos que processam diferentes tipos de objetos de forma uniforme, desde que pertençam à mesma hierarquia.

Vantagem na Extensibilidade: Imagine um método que aceita um parâmetro do tipo Funcionario. Ele poderá receber um Gerente, um Diretor ou qualquer nova classe que venha a ser escrita no futuro como filha de Funcionario, sem que o código desse método precise ser alterado. Isso diminui drasticamente o acoplamento entre as classes.

3. Sobre-escrita de Métodos (Method Overriding)

A sobre-escrita (ou sobrescrita) ocorre quando uma subclasse redefine um método herdado da superclasse para fornecer um comportamento mais específico.

Regras para Sobre-escrita:

  • Assinatura Idêntica: O método na subclasse deve ter exatamente o mesmo nome e a mesma lista de parâmetros (quantidade e tipos) que o método da superclasse.
  • Modificadores de Acesso: O método sobrescrito não pode ser mais restrito que o original. Um método public na mãe não pode ser private ou protected na filha, pois isso violaria o contrato de que "todo objeto da subclasse deve responder às mensagens da superclasse".
  • Retorno: O tipo de retorno deve ser compatível com o definido na superclasse.

Exemplo de Código (Regra de Negócio Diferenciada):

class Funcionario {
    public double getBonificacao() {
        return this.salario * 0.10; // Bônus padrão de 10%
    }
}

class Gerente extends Funcionario {
    @Override
    public double getBonificacao() {
        return this.salario * 0.15; // Gerentes recebem 15%
    }
}

4. A Anotação @Override

Introduzida no Java 1.5, a anotação @Override funciona como um "post-it" ou marcação que notifica o compilador sobre a intenção de sobrescrever um método.

  • Validação em Tempo de Compilação: Se o programador errar o nome do método ou a assinatura, o compilador emitirá um erro, pois não encontrará um método correspondente na classe mãe para sobrescrever.
  • Segurança: Ajuda a evitar erros de lógica sutis, como criar acidentalmente uma sobrecarga (método com nome igual mas parâmetros diferentes) quando a intenção era uma sobre-escrita.

5. Vinculação Dinâmica (Dynamic Binding)

O segredo do polimorfismo reside na forma como a Máquina Virtual Java (JVM) invoca os métodos. Em Java, a decisão de qual método será executado ocorre em tempo de execução (runtime), e não em tempo de compilação.

Quando você chama f.getBonificacao(), a JVM não olha para o tipo da variável (Funcionario), mas sim para o objeto real que está na memória. Se o objeto for um Gerente, a versão do método definida em Gerente será executada, mesmo que a referência usada seja de Funcionario. Este processo é conhecido como vinculação tardia ou dinâmica.

6. Operador instanceof e Downcasting

Embora programar para o geral seja o ideal, às vezes precisamos realizar operações específicas que só existem na subclasse.

  • Downcasting: É o processo de converter uma referência de tipo geral de volta para um tipo específico (ex: transformar um Funcionario de volta em Gerente).
  • Operador instanceof: Antes de fazer o casting, deve-se usar o instanceof para verificar se o objeto realmente pertence àquele tipo, evitando uma exceção do tipo ClassCastException.

Exemplo de Operação Específica:

if (f instanceof Gerente) {
    Gerente g = (Gerente) f; // Downcasting seguro
    g.autentica(1234); // Método que só existe em Gerente
}

7. Restrições: Métodos e Classes final

Nem todos os comportamentos podem ser polimórficos:

  • Métodos final: Um método declarado como final na superclasse não pode ser sobrescrito pelas subclasses. Isso garante que a implementação original seja preservada em toda a hierarquia, o que é útil por questões de segurança.
  • Classes final: Uma classe final não pode possuir subclasses, impedindo qualquer forma de herança ou polimorfismo a partir dela.

Exemplos de Código

1. Nível Básico: Sobre-escrita Simples

Neste exemplo, a subclasse Gerente redefine o comportamento do método herdado para atender a uma regra de negócio específica (bônus de 15% em vez de 10%).

class Funcionario {
    protected double salario;

    public double getBonificacao() {
        return this.salario * 0.10; // Bônus padrão de 10%
    }
}

class Gerente extends Funcionario {
    // Uso da anotação para garantir que o método existe na classe mãe
    @Override 
    public double getBonificacao() {
        return this.salario * 0.15; // Regra específica para Gerentes
    }
}

2. Nível Intermediário: Reaproveitamento com super

Muitas vezes, a subclasse não quer descartar a lógica da superclasse, mas sim complementá-la. Usamos super.metodo() para invocar a versão original.

class Gerente extends Funcionario {
    @Override
    public double getBonificacao() {
        // Chama a lógica de 10% da mãe e adiciona um valor fixo de R$ 1000
        return super.getBonificacao() + 1000.0;
    }
}

3. Nível Avançado: Programando para o "Tipo Geral"

O polimorfismo permite que um método aceite qualquer objeto de uma hierarquia. O método registra abaixo funciona para Gerente, Diretor ou qualquer futuro tipo de Funcionario. 

class ControleDeBonificacoes {
    private double totalDeBonificacoes = 0;

    // O parâmetro 'f' recebe referências polimórficas
    public void registra(Funcionario f) {
        // A JVM decide em tempo de execução qual getBonificacao chamar (Vinculação Dinâmica)
        this.totalDeBonificacoes += f.getBonificacao();
    }

    public double getTotalDeBonificacoes() {
        return this.totalDeBonificacoes;
    }
}

4. Nível Expert: Polimorfismo com Interfaces

Interfaces definem contratos. O código abaixo processa polimorficamente objetos que não possuem parentesco direto (como uma Fatura e um Funcionario), desde que ambos "saibam se pagar".

public interface Payable {
    double getPaymentAmount(); // Contrato abstrato
}

public class PayrollSystemTest {
    public static void main(String[] args) {
        // Array de interfaces que armazena tipos variados
        Payable[] payableObjects = new Payable[3];
        
        payableObjects[0] = new Invoice("0123", "Pneu", 4, 79.95);
        payableObjects[1] = new SalariedEmployee("John", "Smith", "111-11", 800.00);

        for (Payable currentPayable : payableObjects) {
            if (currentPayable != null) {
                // Chamada polimórfica: cada objeto responde à sua maneira
                System.out.printf("Valor devido: $%,.2f%n", currentPayable.getPaymentAmount());
            }
        }
    }
}

5. Nível "Hero": instanceof e Downcasting

Em cenários complexos, você pode precisar identificar o tipo real do objeto em uma coleção genérica para realizar uma ação exclusiva daquela subclasse.

for (Employee currentEmployee : employees) {
    System.out.println(currentEmployee); // Polimorfismo no toString

    // Verifica se o funcionário atual é especificamente um BasePlusCommissionEmployee
    if (currentEmployee instanceof BasePlusCommissionEmployee) {
        // Casting: converte a referência geral de volta para a específica
        BasePlusCommissionEmployee employee = (BasePlusCommissionEmployee) currentEmployee;
        
        // Agora podemos acessar métodos que NÃO existem em Employee
        employee.setBaseSalary(1.10 * employee.getBaseSalary()); 
        System.out.println("Salário base atualizado com 10% de aumento.");
    }
    
    // Volta ao comportamento polimórfico comum
    System.out.printf("Rendimentos: $%,.2f%n", currentEmployee.earnings());
}

3. Polimorfismo com Interfaces (Relacionando Tipos Distintos)

Uma interface é frequentemente usada para permitir que classes não relacionadas por uma hierarquia direta compartilhem comportamentos comuns e sejam processadas polimorficamente.

Quando ocorre polimorfismo dentro de métodos que chamam outros métodos, a JVM utiliza a Pilha de Execução (Stack). Se uma exceção ocorrer, o rastro da pilha (stacktrace) mostra o caminho reverso até o erro.

Dicas & Lembretes

Dicas de Programação e Boas Práticas
  • Sempre utilize a anotação @Override: Ao sobrescrever um método, essa anotação notifica o compilador sobre sua intenção. Se você cometer um erro de digitação no nome do método ou na lista de parâmetros, o compilador emitirá um erro, evitando bugs de lógica difíceis de encontrar.
  • Programe voltado à Interface: É uma "regra de ouro" referenciar objetos por meio de suas interfaces ou superclasses mais genéricas (ex: List lista = new ArrayList();). Isso reduz o acoplamento e permite trocar a implementação interna sem afetar as classes que utilizam o objeto.
  • Aplique o Polimorfismo para Extensibilidade: O polimorfismo permite que você adicione novas subclasses ao sistema sem precisar modificar os métodos que já processam a superclasse. O código torna-se "aberto para extensão e fechado para modificação".
  • Promova a Coesão: Utilize o polimorfismo para substituir grandes estruturas de decisão, como o switch ou vários if/else, por chamadas de métodos. Isso distribui a lógica de negócio entre as subclasses apropriadas.
Lembretes Fundamentais (Regras de Ouro)
  • Objeto Real vs. Referência: Lembre-se que o Java utiliza vinculação dinâmica (dynamic binding). A JVM decide qual método executar em tempo de execução baseando-se no objeto real criado na memória (new), e não no tipo da variável de referência.
  • Restrições de Visibilidade: Ao sobrescrever um método, você não pode torná-lo mais restrito do que o original. Se um método é public na superclasse, ele deve obrigatoriamente ser public na subclasse.
  • Segurança com instanceof: Antes de realizar um downcasting (converter uma referência de tipo geral para um tipo específico), use sempre o operador instanceof para verificar se o objeto realmente pertence àquela subclasse. Isso evita a exceção ClassCastException.
  • A Classe Object é a Raiz: Toda classe em Java, mesmo que não declare explicitamente, herda de java.lang.Object. Isso permite que qualquer objeto no Java possa ser referenciado como um Object, possibilitando o polimorfismo universal para métodos como toString() e equals().
  • Métodos e Classes final: Um método marcado como final não pode ser sobrescrito. Da mesma forma, uma classe marcada como final não pode ter subclasses, o que encerra qualquer possibilidade de comportamento polimórfico a partir dela.
  • Inicialização e Nulos: Em arrays de referências (tipos polimórficos), cada elemento é inicializado como null por padrão. Tentar invocar um método em uma referência nula resultará em um NullPointerException.
