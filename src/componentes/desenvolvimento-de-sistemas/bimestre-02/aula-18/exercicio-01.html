1. Enunciado

Você foi contratado para desenvolver o sistema central de controle de uma empresa de logística e entregas. O sistema deverá gerenciar os veículos da frota, calcular os valores dos fretes com base nas características de cada veículo e registrar as entregas efetuadas através de um menu interativo no console. O projeto exige a aplicação rigorosa do paradigma de Orientação a Objetos para garantir que o sistema seja expansível e seguro.

2. Preparação e Requisitos Técnicos

Para obter a nota máxima, o projeto deverá, obrigatoriamente, demonstrar os seguintes conceitos trabalhados ao longo do semestre:

  • Abstração e Herança: Criação de uma base comum para os veículos da frota, especializando-os em categorias (ex: Caminhão, Van).
  • Encapsulamento: Todos os atributos de estado devem ser privados (private), garantindo a integridade dos dados por meio de Getters e Setters com validações lógicas.
  • Construtores: Inicialização obrigatória de dados essenciais no momento do nascimento dos objetos.
  • Polimorfismo e Sobre-escrita (@Override): O cálculo do frete deve responder de forma diferente dependendo do tipo específico de veículo.
  • Classes Abstratas ou Interfaces: Definição de regras de contrato para as operações da frota.
  • Coleções Dinâmicas (ArrayList): Gerenciamento dinâmico dos veículos cadastrados no sistema.
  • Interação via Console: Um menu interativo (while, switch-case e Scanner) para controle do usuário.

import java.util.ArrayList;

// 1. CONTRATO DO SISTEMA (Interface ou Classe Abstrata)
abstract class Veiculo {
    private String placa;
    private String modelo;
    protected double capacidadeCargaKg;

    public Veiculo(String placa, String modelo, double capacidadeCargaKg) {
        this.placa = placa;
        this.modelo = modelo;
        this.capacidadeCargaKg = capacityValida(capacidadeCargaKg);
    }

    private double capacityValida(double carga) {
        return carga > 0 ? carga : 100; // Validação simples de encapsulamento
    }

    public String getPlaca() { return placa; }
    public String getModelo() { return modelo; }
    public double getCapacidadeCargaKg() { return capacidadeCargaKg; }

    // Método polimórfico que cada tipo de veículo calculará de sua forma
    public abstract double calcularCustoFrete(double distanciaKm);
}

4. O Desafio (Tarefas dos Alunos)

Os alunos deverão completar o sistema atendendo aos seguintes módulos de desenvolvimento:

Módulo 1: Especialização da Frota (Herança e Construtores)

Eles devem criar duas subclasses baseadas na classe abstrata Veiculo:

  • Van: Representa veículos menores. Não possui atributos extras, mas necessita passar os dados corretamente ao construtor do pai (super).
  • Caminhao: Representa veículos pesados. Deve possuir o atributo específico private int eixos; com seu respectivo getter/setter. O construtor deve receber todos os parâmetros, repassando os necessários para a superclasse.

Módulo 2: Regras de Negócio Diferenciadas (Polimorfismo e @Override)

Eles devem sobrescrever o método calcularCustoFrete(double distanciaKm) em ambas as classes sob as seguintes regras financeiras:

  • Na classe Van: O frete cobrado é de R$ 2,50 por quilômetro rodado. Caso a capacidade de carga da van seja superior a 1000 kg, adiciona-se uma taxa fixa de risco de R$ 30,00 ao valor final do frete.
  • Na classe Caminhao: O frete base cobrado é de R$ 4,50 por quilômetro rodado. No entanto, por determinação das praças de pedágio, o valor final deve ser multiplicado pelo número de eixos do caminhão (Valor do Frete = Distância * 4.50 * eixos).

Módulo 3: Consolidação de Dados (Coleções dinâmicas e Iteração)

No case 3 do menu principal, os alunos devem desenvolver um relatório iterando sobre a lista dinâmica frota.

  • O loop deve utilizar a estrutura for-each para ler a lista de forma genérica (for (Veiculo v : frota)).
  • Para cada veículo, deve imprimir na tela: Placa, Modelo, Capacidade e a simulação de quanto custaria um frete de 100 quilômetros utilizando aquele veículo. O polimorfismo deve agir aqui para trazer o cálculo correto sem que o menu precise saber se o veículo é uma van ou um caminhão.

5. Orientações Finais e Critérios de Correção

Oriente os alunos a prestarem atenção nos seguintes pontos de validação:

  • Pilar da Abstração: A classe Veiculo é abstrata. Se o aluno tentar dar um new Veiculo(...) dentro do código, o compilador gerará um erro.
  • Tratamento do Buffer: Relembre-os de que ao usar leitor.nextDouble() ou leitor.nextInt() antes de ler uma String com leitor.nextLine(), é obrigatório capturar a quebra de linha residual para o programa não pular entradas.
