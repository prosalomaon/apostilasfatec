Especificação de Requisitos: JavaLog Express

Para garantir que o software seja desenvolvido em conformidade com as necessidades da transportadora, você deve seguir estritamente os requisitos e regras de negócio mapeados abaixo.

1. Regras de Negócio (RN)

As Regras de Negócio determinam como a empresa funciona e como os cálculos devem ser validados. Elas são imutáveis pelo programador.

  • RN01 - Cálculo de Frete para Vans: O valor base do frete para veículos da categoria Van é fixado em R$ 2,50 por quilômetro rodado.
  • RN02 - Taxa de Carga para Vans: Se uma Van possuir uma capacidade de carga superior a 1000 kg, o sistema deve obrigatoriamente aplicar uma taxa fixa adicional de risco de R$ 30,00 ao valor final do frete.
  • RN03 - Cálculo de Frete para Caminhões: O valor base do frete para veículos da categoria Caminhão é fixado em R$ 4,50 por quilômetro rodado.
  • RN04 - Multiplicador de Eixos: Devido aos custos de pedágio em rodovias, o valor do frete de um Caminhão deve ser multiplicado pelo seu número de eixos (Fórmula: distancia * 4.50 * eixos).
  • RN05 - Integridade de Carga: O sistema não pode aceitar veículos com capacidade de carga menor ou igual a zero. Caso o usuário tente digitar um valor inválido, a capacidade deve ser ajustada automaticamente para um valor padrão seguro de 100 kg.

2. Requisitos Funcionais (RF)

Os Requisitos Funcionais descrevem as ações que o usuário deve ser capaz de realizar dentro do sistema (as funcionalidades).

  • RF01 - Cadastrar Van: O sistema deve permitir ao usuário cadastrar uma Van informando obrigatoriamente a Placa, o Modelo e a Capacidade de Carga (em kg).
  • RF02 - Cadastrar Caminhão: O sistema deve permitir ao usuário cadastrar um Caminhão informando obrigatoriamente a Placa, o Modelo, a Capacidade de Carga (em kg) e a Quantidade de Eixos.
  • RF03 - Armazenamento Dinâmico: O sistema deve armazenar todos os veículos cadastrados em memória de forma dinâmica, permitindo novos cadastros sem um limite fixo pré-definido.
  • RF04 - Emitir Relatório de Frota: O sistema deve gerar um relatório detalhado listando todos os veículos cadastrados, exibindo seus atributos específicos.
  • RF05 - Simular Custo de Entrega: Junto ao relatório de frota (RF04), o sistema deve exibir uma simulação automática do custo de um frete para uma distância padrão de 100 quilômetros para cada veículo da lista.
  • RF06 - Menu de Navegação: O sistema deve prover um menu interativo no console para que o usuário escolha qual funcionalidade deseja executar (Cadastrar, Listar ou Encerrar).

3. Requisitos Não Funcionais (RNF)

Os Requisitos Não Funcionais definem as restrições técnicas, qualidades e tecnologias que devem ser usadas para construir o software.

  • RNF01 - Paradigma de Programação: O sistema deve ser desenvolvido obrigatoriamente utilizando o paradigma de Programação Orientada a Objetos (POO).
  • RNF02 - Tecnologia e Linguagem: O projeto deve ser codificado na linguagem Java, utilizando recursos normatizados do JDK.
  • RNF03 - Interface com Usuário: A interface do sistema deve ser estritamente em modo texto (Console/Terminal), utilizando a entrada padrão de dados do teclado.
  • RNF04 - Proteção de Dados (Encapsulamento): Todos os atributos das classes de entidade (Veiculo, Van, Caminhao) devem ser fortemente encapsulados usando o modificador de acesso private, impedindo alterações diretas externas.
  • RNF05 - Extensibilidade (Polimorfismo): O método de cálculo de frete deve ser abstrato na classe mãe e submetido ao polimorfismo dinâmico em tempo de execução através da anotação @Override. O laço que exibe o relatório não pode fazer checagens manuais de tipo (como usar instanceof).
  • RNF06 - Persistência em Memória: Os dados serão mantidos de forma volátil em memória RAM através da coleção ArrayList, não sendo necessário o uso de banco de dados nesta versão do protótipo.
