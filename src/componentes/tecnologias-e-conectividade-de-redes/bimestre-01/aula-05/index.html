1. Introdução: Do Conceito à Configuração

No encontro anterior estudamos os fundamentos das VLANs e o padrão de marcação IEEE 802.1Q. Agora vamos colocar esses conceitos em prática no simulador Cisco Packet Tracer, configurando Portas de Acesso (Access Ports) e Links de Tronco (Trunk Ports) em dois switches comutados.

Serão analisados os comandos de interface de linha de comando (CLI), o comportamento dos quadros Ethernet com a marcação IEEE 802.1Q e as técnicas de solução de problemas (troubleshooting), conforme previsto na ementa da disciplina.

Requisito: Cisco Packet Tracer instalado (versão 8.0 ou superior).

2. Fundamentos Teóricos da Operação das Portas

Antes da execução dos comandos, é essencial compreender a distinção funcional entre os dois tipos de portas em um ambiente de comutação:

A. Portas de Acesso (Access Ports)

São interfaces conectadas a dispositivos finais (computadores, impressoras, servidores). Cada porta de acesso é associada a uma única VLAN. Os quadros que entram e saem dessas portas são do tipo convencional (untagged — sem etiqueta 802.1Q). O switch atribui internamente a tag da VLAN correspondente assim que o quadro entra na interface e remove a tag antes de entregar o quadro ao host final, garantindo transparência para as placas de rede dos computadores.

B. Portas de Tronco (Trunk Ports)

São interfaces de interconexão entre switches ou entre switch e roteador. Têm a função de transportar o tráfego de múltiplas VLANs simultaneamente através de um único enlace físico. Para diferenciar a qual VLAN cada quadro pertence ao atravessar o cabo, o switch insere o cabeçalho IEEE 802.1Q de 4 bytes (contendo o identificador de VLAN de 12 bits, TPID 0x8100 e os bits de prioridade de QoS).

C. VLAN Nativa (Native VLAN)

Por padrão no padrão IEEE 802.1Q, quadros pertencentes à VLAN Nativa (geralmente a VLAN 1) trafegam pelo link de tronco sem a adição da etiqueta de 4 bytes (untagged). Se um switch recebe um quadro sem tag em uma porta tronco, ele assume que esse quadro pertence à sua VLAN Nativa configurada.

4. Roteiro de Configuração CLI (Passo a Passo)

Passo 1 — Criação e Nomeação das VLANs nos Switches (SW-1 e SW-2)

A criação do banco de dados de VLANs deve ser realizada em ambos os switches para que reconheçam os identificadores numéricos.

SW-1# configure terminal
SW-1(config)# vlan 10
SW-1(config-vlan)# name Vendas
SW-1(config-vlan)# exit
SW-1(config)# vlan 20
SW-1(config-vlan)# name Engenharia
SW-1(config-vlan)# exit

Repetir exatamente os mesmos comandos no switch SW-2.

Passo 2 — Configuração das Portas de Acesso

Definição do modo de operação estático da porta como acesso e associação à respectiva VLAN.

Configuração no Switch SW-1:

SW-1(config)# interface FastEthernet 0/1
SW-1(config-if)# switchport mode access
SW-1(config-if)# switchport access vlan 10
SW-1(config-if)# exit

SW-1(config)# interface FastEthernet 0/2
SW-1(config-if)# switchport mode access
SW-1(config-if)# switchport access vlan 20
SW-1(config-if)# exit

Configuração no Switch SW-2:

SW-2(config)# interface FastEthernet 0/1
SW-2(config-if)# switchport mode access
SW-2(config-if)# switchport access vlan 10
SW-2(config-if)# exit

SW-2(config)# interface FastEthernet 0/2
SW-2(config-if)# switchport mode access
SW-2(config-if)# switchport access vlan 20
SW-2(config-if)# exit

Passo 3 — Configuração do Link de Tronco (Trunking IEEE 802.1Q)

Configuração da interface de interconexão Fa0/24 em ambos os switches para multiplexar e transportar quadros com a etiqueta de 4 bytes do padrão 802.1Q.

Configuração no Switch SW-1 e SW-2 (Porta Fa0/24):

SW-1(config)# interface FastEthernet 0/24
SW-1(config-if)# switchport mode trunk
SW-1(config-if)# switchport trunk allowed vlan 10,20
SW-1(config-if)# exit

Nota de Segurança

O comando switchport trunk allowed vlan 10,20 limita o tráfego do link aos grupos autorizados, restringindo tempestades de broadcast desnecessárias enviadas pela rede. Sem essa restrição, o trunk transportaria todas as VLANs existentes (1–4094), incluindo VLANs não previstas no projeto.

Passo 4 — Alteração Opcional da VLAN Nativa

Para prevenir ataques de VLAN Hopping ou incompatibilidades de tráfego não etiquetado, é recomendável alterar a VLAN Nativa padrão (VLAN 1) para uma VLAN sem portas de acesso ativas.

SW-1(config)# interface FastEthernet 0/24
SW-1(config-if)# switchport trunk native vlan 99
SW-1(config-if)# exit

Atenção: Se a VLAN nativa for diferente nas duas pontas do tronco, o switch gerará alertas de inconsistência de CDP/802.1Q.

5. Diagnóstico, Verificação e Troubleshooting

Para validar se os domínios de broadcast estão isolados corretamente e se o tronco está funcionando, os seguintes comandos devem ser executados via CLI:

A. Verificação da Tabela de VLANs

SW-1# show vlan brief

O que validar: confirma se as portas Fa0/1 e Fa0/2 estão atribuídas corretamente às VLANs 10 e 20 e se a porta Fa0/24 não aparece na lista (pois virou trunk).

Resultado esperado:

VLAN Name                             Status    Ports
---- -------------------------------- --------- -------------------------------
1    default                          active    Fa0/3, Fa0/4, Fa0/5, Fa0/6 ...
10   Vendas                           active    Fa0/1
20   Engenharia                       active    Fa0/2

B. Verificação do Estado do Tronco

SW-1# show interfaces trunk

O que validar: exibe o modo (trunk), o protocolo de encapsulamento (802.1q), a VLAN Nativa ativa e as VLANs permitidas no enlace.

Resultado esperado:

Port        Mode         Encapsulation  Status        Native vlan
Fa0/24      on           802.1q         trunking      1

Port        Vlans allowed on trunk
Fa0/24      10,20

Port        Vlans allowed and active in management domain
Fa0/24      10,20

Port        Vlans in spanning tree forwarding state and not pruned
Fa0/24      10,20

C. Teste de Conectividade Lógica (Ping no Packet Tracer)

Teste 1 — Mesma VLAN / Hosts Distintos: executar ping 192.168.10.20 a partir do PC-1 (VLAN 10) em direção ao PC-3 (VLAN 10 em outro switch).

Resultado esperado: Sucesso (Reply). O quadro sai de PC-1, entra sem tag na porta Fa0/1 de SW-1, recebe a tag 10 ao entrar no tronco Fa0/24, atravessa o cabo etiquetado com VLAN ID 10, chega ao SW-2, que remove a tag e entrega o quadro limpo ao PC-3.

Teste 2 — VLANs Distintas / Camada 2 Pura: executar ping 192.168.20.10 a partir do PC-1 (VLAN 10) em direção ao PC-2 (VLAN 20 no mesmo switch).

Resultado esperado: Falha (Request Timed Out). Mesmo estando no mesmo switch físico, a separação lógica de portas bloqueia o encaminhamento de broadcast e unicast entre VLANs diferentes, exigindo um dispositivo de Camada 3 (roteador) para comunicação.

Troubleshooting Rápido

  • Ping entre switches falha na mesma VLAN: verifique se a VLAN foi criada nos dois switches e se o comando switchport trunk allowed vlan inclui a VLAN desejada.
  • Trunk não sobe (status down): confira se as duas extremidades estão com switchport mode trunk consentâneo (mismatch de modo DTP) e se os cabos estão nas portas corretas.
  • Alertas de nativa inconsistente: as VLANs nativas das duas pontas do tronco precisam ser idênticas.
  • Host sem comunicação mesmo na mesma VLAN: confira o endereço IP, a máscara e a porta de acesso no show vlan brief.

6. Quadro Comparativo: Porta de Acesso vs. Porta de Tronco

Parâmetro Porta de Acesso (Access Port) Porta de Tronco (Trunk Port)
Conectividade típica Dispositivos Finais (PC, Impressoras, Servidores). Dispositivos de Rede (Switch para Switch, Switch para Roteador).
Quantidade de VLANs Transporta tráfego de apenas 1 VLAN por vez. Transporta tráfego de múltiplas VLANs simultaneamente.
Cabeçalho IEEE 802.1Q Não possui tag no cabo (untagged). Insere a tag de 4 bytes contendo o VLAN ID nos quadros (tagged).
Tratamento da VLAN Nativa Inexistente (porta pertence a uma VLAN estática). Quadros da VLAN Nativa passam sem tag.
Comandos principais no IOS switchport mode access
switchport access vlan <id>		 switchport mode trunk
switchport trunk allowed vlan <ids>

Dicas & Lembretes

  • Porta de acesso: conecta dispositivos finais; quadros sempre untagged; pertence a uma única VLAN.
  • Porta de tronco: conecta switches/roteadores; transporta várias VLANs; quadros saem tagged com 802.1Q.
  • VLAN Nativa: por padrão a VLAN 1; seus quadros atravessam o trunk sem tag. Troque-a no laboratório por uma VLAN sem portas de acesso.
  • Restrição de tronco: sempre use switchport trunk allowed vlan para permitir apenas as VLANs do projeto.
  • Show commands: show vlan brief confirma portas de acesso; show interfaces trunk confirma o estado do enlace de tronco.

Como Aplicar na Prática

  • Projeto de redes: atribua portas de acesso aos hosts de cada setor e reserve portas de tronco apenas para a interconexão de switches e o uplink para o roteador.
  • Segurança: restrinja as VLANs permitidas no trunk e troque a VLAN nativa padrão para evitar ataques de VLAN Hopping.
  • Escalabilidade: ao adicionar um novo switch no rack, replique o banco de VLANs (comandos vlan + name) e configure o novo enlace de tronco antes de ativar as portas dos usuários.
  • Troubleshooting: use show vlan brief e show interfaces trunk como primeiro passo de diagnóstico em casos de host "desaparecido" ou enlace inoperante.
